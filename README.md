# snake-python

My Snake implementation in Python for my kids.

This project is also a small learning exercise in coding with AI assistance, so the code and this README evolve step by step
as design decisions get made along the way.

## Project structure

- `utils.py` — shared types used across the project: `Coordinate`, `Direction`,
  `TileType`, `Valuable`.
- `snake.py` — the `Snake` class: holds a snake's own state (`length`,
  `direction`). It does **not** know where it is on the map.
- `map.py` — the `Map` class: owns the game board, tracks where everything is,
  and answers "what is at this position" queries.
- `game.py` *(not implemented yet)* — will own and coordinate `Map`, `Snake`,
  and `Valuable` instances, and will be responsible for assigning snake IDs.

## Map

The map has two dimensions: width and height. The `(0, 0)` coordinate is at
the top-left corner, and the y-axis is "upside-down" (increasing downward):

```text
                                         x
                ------------------------→
                ┌───┬───┬───┬───┬───┬───┐
            │   │   │   │   │   │   │   │
            │   ├───┼───┼───┼───┼───┼───┤
            │   │   │   │   │   │   │   │
            │   ├───┼───┼───┼───┼───┼───┤
            │   │   │   │   │   │   │   │
            │   ├───┼───┼───┼───┼───┼───┤
            │   │   │   │   │   │   │   │
            │   ├───┼───┼───┼───┼───┼───┤
            │   │   │   │   │   │   │   │
            │   ├───┼───┼───┼───┼───┼───┤
            │   │   │   │   │   │   │   │
            ↓ y └───┴───┴───┴───┴───┴───┘
```

The example above shows a 6×6 map. In the game, width and height can be any
values.

### No matrix, computed positions instead

The map is **not** represented with a matrix data structure.
Instead of storing a grid in memory, the `Map` class stores *where things
are* and computes the answer to "what is at position (x, y)" on demand. A UI
layer can later render this as a grid, but internally there is no matrix
backing the map.

Concretely, `Map` stores:

- `valuables: dict[Coordinate, Valuable]` — maps a coordinate to the
  valuable placed there (e.g. an apple).
- `snakes: dict[int, set[Coordinate]]` — maps a snake ID to the set of
  coordinates its body currently occupies.

### Responsibilities

The `Map` class is responsible for:

- **Spatial state.** It is the single source of truth for what occupies
  which coordinate — valuables and snake bodies.
- **Placing valuables** (`set_valuable`, `remove_valuable`) on empty tiles
  only.
- **Placing snakes** (`set_snake`), given a starting coordinate, a snake ID,
  and a `Snake` object to read its
  `length` and `direction` from. The body is laid out tile by tile from the
  starting point, opposite to the snake's facing direction, without
  wrapping around the map edges. If any tile along the way is not free, the
  whole placement is rolled back and `set_snake` returns `False`.
- **Answering tile queries** (`what_at`) — returns whether a coordinate is a
  wall (out of bounds), a valuable, a snake, or an empty tile.
- **Printing a simple text representation** of the board (`print`), for
  quick debugging/inspection before a real UI exists.

What `Map` explicitly does **not** own:

- **Snake identity/behavior.** `Map` reads a `Snake`'s `length` and
  `direction` once, while placing it, but does not store the `Snake` object
  itself and does not track direction changes or movement logic — that is
  the `Snake` class's responsibility.
- **Snake ID assignment.** IDs are generated by the caller (eventually the
  `Game` class) and passed into `set_snake`, so that the same ID can be
  used to look up the corresponding `Snake` object elsewhere. `Map` just
  uses whatever ID it's given as a dictionary key.

### What it's good for right now

At this stage, `Map` can:

- Be created with a given width and height.
- Have valuables placed on and removed from empty tiles.
- Have one or more snakes placed on it, with their body laid out based on a
  starting coordinate and the snake's length/direction, without going out
  of bounds.
- Answer what kind of tile is at any given coordinate.
- Print a simple text view of the board for debugging.

It does **not** yet support movement/stepping the snake forward, collision
resolution during movement, or multiple valuable types — those are planned
for later, once `Snake` and `Game` are further along.
